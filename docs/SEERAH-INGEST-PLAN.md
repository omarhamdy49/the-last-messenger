# خطة إدخال السيرة النبوية الكاملة إلى البوابة

**التاريخ:** 2026-08-12
**النطاق:** إدخال 14 حقبة (milestones) و57 محطة (events) و190 نقطة زمنية داخلية (timeline items) من `docs/rasool-allah/seiraah-docs` إلى قاعدة البيانات، ثم التحقق من ظهورها كاملة في الواجهة العامة.

### 1.2 نمطان مختلفان للمحتوى — مهم للـparser

**النمط أ — منظّم بالكامل (32 ملف: من `5.3` حتى `14.3`):**

```
🛡️ المحطة الثانية: حسم النفاق.. تشبث ابن سلول وجلاء الخونة
1. تدخل رأس النفاق.. "يا محمد، أحسن في مواليّ"
التاريخ: 1 ذو القعدة 2 هـ
المكان: معسكر المسلمين خارج حصون بني قينقاع
<نص>
2. …
```
→ كل نقطة تعطي: `title` + `hijri_date` + `location` + `description`. تعيين مباشر على `seerah_event_timeline_items`، ويُشتق منها `hijri_date`/`hijri_year`/`hijri_month`/`location` للحدث الأب.

**النمط ب — سردي بدون تواريخ (23 ملف: من `1.3` حتى `5.2`):**
نفس بنية `N. عنوان` + نص، لكن **بدون** سطري `التاريخ:` و`المكان:` → تُدخل كـ timeline items بلا تاريخ، وتُملأ تواريخ الحدث الأب يدوياً/من `map.md`.

**استثناء — ملفان بلا ترقيم (`1.1 المقدمة والبيئة`، `1.2 عام الفيل`):**
عناوينهما الفرعية سطور مبدوءة بإيموجي (🌍 / 🏜️ / 🕋). نسخة الـHTML المقابلة تحتوي على `<h2>`/`<h3>` صريحة — **تُقرأ النقاط الفرعية لهذين الملفين من `output_html/` بدل الـmarkdown.**

### 1.3 تعارض بين `map.md` وبنية المجلدات ⚠️ **قرار مطلوب**

`map.md` يذكر 14 قسماً × 3 محطات = 42، بينما المجلدات الفعلية فيها 57 محطة، **والحدود مختلفة**:

| المجلد | محتواه الفعلي | ما يقابله في `map.md` |
| :--- | :--- | :--- |
| 1 | المقدمة → غار حراء (6 محطات) | القسم 1 + بداية القسم 2 |
| 2 | الدعوة السرية → حصار الشِعب | باقي القسم 2 + القسم 3 |
| 3 | عام الحزن → ليلة العقبة | القسم 4 + بداية 5 |
| 4 | ليلة الهجرة → أشرق البدر | باقي 5 + بداية 6 |
| 5 | بناء الدولة → التموضع لبدر | باقي 6 + بداية 7 |
| 6 | يوم الفرقان → إدارة الأسرى | القسم 7 |
| **7** | **بنو قينقاع، ابن سلول، السويق، كعب بن الأشرف** | **غير موجود في `map.md` إطلاقاً** |
| 8–14 | أُحد → الرفيق الأعلى | الأقسام 8–14 (متطابقة) |

**التوصية:** اعتماد **المجلدات الـ14 كمصدر الحقيقة للحِقَب** (لأنها تحوي محتوى أكثر)، مع استعارة العناوين القصصية والنطاقات الزمنية من `map.md` حيث تتطابق، وصياغة عنوان جديد للمجلد 7 (مقترح: *«تطهير الجبهة الداخلية.. غدر بني قينقاع وتصفية رؤوس الفتنة»*، شوال 2 هـ – ذو الحجة 2 هـ).

### 1.4 الكتب الأصلية — `seiraah/*.pdf` ⚠️ **حاجز تقني**

| الملف | الصفحات | طبقة نصية |
| :--- | :--- | :--- |
| مختصر الجامع في السيرة النبوية — ج1 | 506 | ❌ **صور ممسوحة فقط** |
| مختصر الجامع في السيرة النبوية — ج2 | 456 | ❌ **صور ممسوحة فقط** |

962 صفحة بلا أي نص قابل للاستخراج (`get_text()` = 0 حرف على عيّنة كل 25 صفحة). المقارنة الآلية للتأكد من عدم نقصان أي حدث **تتطلب OCR**.
`tesseract` مثبّت محلياً مع حزمة `ara` (163 لغة متاحة) → التنفيذ ممكن، التكلفة المقدّرة **45–75 دقيقة معالجة** لكامل الجزأين بدقة 300dpi.

الكتب الأخرى في `docs/rasool-allah/` **بها نص**، لكنها ليست تسلسلاً زمنياً للسيرة:
- *الرسول الإنسان* (السويدان، 405ص، فهرس من 104 مدخل) → شمائل وأخلاق، **مصدر ممتاز لموديول مستقبلي** لا لهذه الخطة.
- *رجال حول الرسول* (313ص) → تراجم صحابة، يخدم موديول People لا Seerah.
- *دروس من السيرة النبوية* (سميرة الزايد، 202ص) → دروس مستخلصة، مفيد لحقل «العبر» لاحقاً.

### 1.5 محادثة Gemini ⚠️ **محجوب**

`https://gemini.google.com/app/f84d4079124eb730` يتطلب جلسة Google الخاصة بك.
إضافة **Claude in Chrome غير متصلة** حالياً (`tabs_context_mcp` يرجع "not connected"). المتصفح المدمج في التطبيق لن يملك جلستك.
**المطلوب منك:** تثبيت/تسجيل دخول الإضافة (https://chromewebstore.google.com/detail/fcoeoabgfenejglbffodgkkbkcdhcgfn) ثم إعادة المحاولة، أو لصق محتوى المحادثة هنا.

## 2. حالة النظام الحالية

### 2.1 قاعدة البيانات — شبه فارغة

```
seerah_milestones               0      ← لا شيء
seerah_events                   3      ← بيانات تجريبية (first-revelation, hijrah-to-madinah, battle-of-badr)
seerah_event_types             11      ← جاهزة ومترجمة
seerah_event_timeline_items     0
seerah_participants             0
seerah_event_translations       6      ← ar+en للأحداث الثلاثة
seerah_milestone_translations   0
```

الأحداث الثلاثة الموجودة: `seerah_milestone_id = NULL`, `era = NULL`, `phase = NULL` → لن تظهر في مسار الحِقَب على الإطلاق (`buildJourney()` يستبعد الحِقَب فارغة الأحداث، وهذه الأحداث بلا حقبة أصلاً).

### 2.2 المخطط (Schema) — كافٍ تماماً، لا حاجة لهجرات جديدة

| الجدول | ملاحظة |
| :--- | :--- |
| `seerah_milestones` (+ `_translations`) | slug, order_index, icon, color, gradient, hijri_label_from/to, hijri_year_from/to, gregorian_year_from/to, is_active — ويقابله `title/subtitle/description` لكل لغة |
| `seerah_events` (+ `_translations`) | slug, hijri_date/year/month/day, gregorian_date/year, `seerah_event_type_id`, `seerah_milestone_id`, era, phase, importance, status, is_pivotal, is_featured, location, lat/lng, featured_image, gallery(JSON), statistics(JSON), related_article_id, display_order, views_count |
| `seerah_event_timeline_items` (+ `_translations`) | display_order + title/description لكل لغة |
| `seerah_participants` | event_id, participant_type, participant_id, name(JSON), role(enum), description |
| Enums | `EventEra`: pre_birth\|childhood\|pre_revelation\|mecca\|medina — `EventPhase`: early_life\|mecca\|hijra\|final_years |

### 2.3 فجوات لوحة الإدارة ⚠️

`StoreSeerahEventRequest` ونموذج `admin/seerah-events/create.blade.php` يغطيان **16 حقلاً فقط**. **ناقص بالكامل:**

| الحقل الناقص | تعرضه الواجهة العامة؟ |
| :--- | :--- |
| `era` | ✅ `eraLabel` في صفحة الحدث |
| `phase` | ✅ `phaseLabel` + شارة |
| `is_pivotal` | ✅ شارة «حدث مفصلي» في `event-timeline.blade.php:279` |
| `statistics` (JSON) | ✅ بطاقات إحصائية أعلى الصفحة (`event.blade.php:458`) |
| `gallery` (JSON) | ✅ قسم معرض الصور (`event.blade.php:586`) |
| `hijri_month` / `hijri_day` | ✅ (ترتيب زمني) |
| **عناصر الخط الزمني الداخلي** | ✅ قسم كامل (`event.blade.php:509`) |
| **الشخصيات/المشاركون** | ✅ قسمان: رئيسي + شريط جانبي (`event.blade.php:554, 666`) |

بالمقابل: **إدارة الحِقَب (`StoreSeerahMilestoneRequest`) مكتملة** — كل الحقول مغطاة، لا عمل مطلوب هناك.

### 2.4 الواجهة العامة — مبنية بالفعل وبمستوى premium

الصفحات الأربع موجودة (2,445 سطر): مسار الحِقَب، دليل الأحداث بفلاتر، صفحة الحدث بنمطين (مقالي / خط زمني غامر)، مع dark mode و scroll-spy و RTL. **كل الأقسام مشروطة بوجود البيانات** — أي أن السبب في «نقص الظهور» هو نقص البيانات لا نقص الواجهة.

**عطل مؤكد:** `public/assets/event/event-img.png` **غير موجود** رغم استخدامه كصورة احتياطية في موضعين (`event.blade.php:377`, `event-timeline.blade.php:251`) → كل حدث بلا `featured_image` سيعرض صورة مكسورة (404) في الـhero.

## 3. الخطة التنفيذية

### المرحلة 0 — قرارات وحواجز (قبل أي كود)

| # | البند | الحالة |
| :--- | :--- | :--- |
| 0.1 | اعتماد تقسيم المجلدات الـ14 كحِقَب + صياغة عنوان القسم 7 | ⏳ بانتظارك |
| 0.2 | ماذا نفعل بالأحداث التجريبية الثلاثة: تُحدَّث وتُربط، أم تُحذف؟ | ⏳ بانتظارك |
| 0.3 | هل ننفّذ OCR لـ962 صفحة الآن أم نؤجّله بعد الإدخال؟ | ⏳ بانتظارك |
| 0.4 | إتاحة محادثة Gemini (توصيل إضافة Chrome أو لصق المحتوى) | ⏳ بانتظارك |
| 0.5 | الصور الـ170: من ينتجها؟ (ليست قابلة للتوليد من هنا) | ⏳ بانتظارك |

### المرحلة 1 — أمر استيراد idempotent

**الملف:** `app/Console/Commands/ImportSeerahContentCommand.php`
**التوقيع:** `php artisan seerah:import {--path=} {--dry-run} {--force} {--section=}`

يتبع نمط `ImportMuslimScholarsSahabaCommand` القائم (معاملات مجزّأة، فحص تصادم الـslug مسبقاً، بصمات provenance، دعم dry-run).

**المنطق:**
1. قراءة `map.md` → 14 صف (عنوان قصصي، نطاق هجري، نطاق ميلادي).
2. لكل مجلد قسم: `upsert` على `seerah_milestones` بمفتاح `slug` + `syncTranslations(['ar' => [...]])`.
3. لكل ملف محطة: parser يتعامل مع النمطين (أ/ب) + الاستثناء (قراءة HTML للملفين 1.1 و1.2):
   - السطر الأول → `title` (بعد تجريد الإيموجي و«المحطة الأولى:»).
   - أول فقرة → `description`.
   - النص الكامل مُحوّل لـHTML → `content`.
   - كل `N. عنوان` → صف في `seerah_event_timeline_items` مع `display_order`.
   - `التاريخ:` → `hijri_date` للنقطة، وأول تاريخ في الملف → `hijri_date/year/month` للحدث.
   - `المكان:` → `location`.
4. تخمين `seerah_event_type_id` من كلمات مفتاحية في العنوان (غزوة/معركة→battle، وحي/نزل→revelation، هجرة→migration، صلح/معاهدة/بيعة→treaty، ولادة/ميلاد→birth، وفاة/الرفيق الأعلى→death، معجزة/الإسراء→miracle، رسائل/وفد→delegation، وإلا→other). **يُطبع تقرير بالتخمينات للمراجعة اليدوية.**
5. اشتقاق `era`/`phase` من رقم القسم (1→pre_birth/childhood + early_life، 2–4→mecca، 5→hijra، 6–14→medina/final_years).
6. `is_pivotal = true` للمحطات المحورية (بدر، أُحد، الخندق، الحديبية، خيبر، فتح مكة، حنين، تبوك، حجة الوداع، الوفاة، الهجرة، الإسراء والمعراج، عام الحزن، بدء الوحي).
7. `status = 'draft'` افتراضياً، `--force` أو مراجعة لاحقة تنشرها.
8. الكتابة عبر `syncTranslations()` حصراً (لا إسناد مباشر — راجع قسم Translatable في `CLAUDE.md`).

**فحص واحد قابل للتشغيل:** `tests/Feature/Seerah/ImportSeerahContentTest.php` — يستورد ثلاث حالات تمثيلية (نمط أ، نمط ب، الاستثناء HTML) ويؤكد: عدد timeline items، صحة التواريخ المستخرجة، وأن إعادة التشغيل لا تُنشئ صفوفاً مكرّرة.

### المرحلة 2 — سد فجوات لوحة الإدارة

لأن الاستيراد آلي، لكن **التحرير اللاحق يجب أن يكون ممكناً من البوابة**:

1. توسيع `StoreSeerahEventRequest` / `UpdateSeerahEventRequest`: `era`, `phase`, `is_pivotal`, `hijri_month`, `hijri_day`, `statistics` (array), `gallery` (array of files/strings).
2. توسيع `admin/seerah-events/{create,edit}.blade.php`: حقول مقابلة + **repeater لعناصر الخط الزمني** + **repeater للمشاركين** (بنفس نمط تبويبات اللغة القائم).
3. `SeerahEventService::create/update` → مزامنة العلاقتين (حذف/إضافة العناصر المرسلة).
4. تعريب كامل للحقول الجديدة في `resources/lang/ar/` (افتراضي عربي حسب `CLAUDE.md`).

### المرحلة 3 — الوسائط

1. إنشاء `public/assets/event/event-img.png` (صورة احتياطية عامة) — **يصلح 404 مؤكداً**.
2. إنتاج الصور الـ170 من ملفات `prompts.md` خارجياً، ثم أمر `seerah:attach-media` يربط كل صورة بحدثها عبر اسم الملف (`{section}.{station}.cover.webp` → `featured_image`، والباقي → `gallery`).
3. تحويل لـwebp + أحجام responsive عبر Spatie Media Library.

### المرحلة 4 — التحقق من الاكتمال مقابل الأصل (يعتمد على 0.3)

1. `ocrmypdf`/`tesseract -l ara` على الجزأين → نص خام في `storage/app/seerah-ocr/`.
2. استخراج فهرس الغزوات والأحداث من النص (`غزوة`, `سرية`, `عام`, `بيعة`, `صلح`).
3. مطابقته مع الـ57 محطة → **تقرير فجوات** بالأحداث الموجودة في الكتاب وغير الموجودة عندنا (مثال متوقع: سرايا صغيرة، وفود العام التاسع، بعض الغزوات الثانوية).
4. قرار: إضافة المفقود كمحطات جديدة أم قبول النطاق الحالي.

### المرحلة 5 — التحقق من الواجهة (بعد امتلاء البيانات)

1. `php artisan optimize:clear` (الكاش 1800 ثانية على مسار الحِقَب وصفحة الحدث).
2. فحص آلي لكل الـ57 رابطاً: حالة 200، ووجود كل قسم متوقّع (وصف، محتوى، خط زمني، شخصيات، معرض، خريطة).
3. فحص بصري responsive عبر متصفح التطبيق: 375px / 768px / 1280px، في الوضعين الفاتح والداكن، مع تأكيد RTL.
4. تقرير نهائي: جدول 57 صفاً × الأقسام المعروضة، وأي حقل ناقص.
